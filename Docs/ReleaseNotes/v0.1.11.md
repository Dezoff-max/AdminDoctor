## AdminDoctor v0.1.11

Security hardening and release packaging fixes.

Security:
- The privileged helper accepts XPC connections only from the AdminDoctor app signed by the same team as the helper. An unsigned or ad-hoc signed helper refuses every connection.
- Privileged cleanup quarantine moved from `/Users/Shared` to the root-only `/Library/Application Support/AdminDoctor/Quarantine`. Symlinked, foreign-owned, or group/world-writable quarantine directories are rejected.
- The unused administrator password prompt at launch is removed.
- Network toolkit hosts that start with `-` are rejected, so input cannot be parsed as a `ping` or `traceroute` option.
- Command execution uses an explicit allow-list of executables instead of a short deny-list.
- Installation notes no longer suggest disabling Gatekeeper system-wide.

Packaging:
- `Info.plist` now carries the app version and build number.
- `NSLocalNetworkUsageDescription` is set in English and Russian for the macOS local network prompt.
- The offline OUI vendor data is copied into the app bundle. Earlier DMGs could only load it on the Mac that built them.
- Release DMGs are built in the release configuration by GitHub Actions.

Notes:
- Items quarantined by earlier versions stay in `/Users/Shared/AdminDoctor/PrivilegedCleanup` and are not migrated.
- Helper cleanup needs a Developer ID signed build; it does not work in unsigned builds.
